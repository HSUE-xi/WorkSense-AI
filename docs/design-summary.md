# WorkSense-AI 設計總結

> 依 2026 全國 AI 專題創意競賽・富雅居實業命題「AI 智慧工時自動辨識與 MES 即時回填系統」所做的設計決策。名詞定義見 [GLOSSARY.md](../GLOSSARY.md)，關鍵取捨見 [docs/adr/](./adr/)。

## 命題對照

| 命題要求 | 本設計的對應 |
|---|---|
| 人員掃描工單後開始記錄工時 | 工作站平板依序掃員工證、工單，開始作業段 |
| 判斷工作時間與閒置時間 | AI 判定四種工作狀態，換算有效工時、在場閒置、離開 |
| 基本：產出工單工時 | 工單有效工時（人時），回填 MES |
| 進階：效率建議、多人比較、最佳模式 | 工作模式指標 → 同產品標竿 → LLM 依指標產生效率建議 |

## 定位

- 獨立的工時辨識服務，回填企業既有 MES；Demo 時以內建工單頁面扮演 MES。（ADR-0003）
- 量測核心是**作業員**，不是工單。

## 現場流程

1. 每個工作站配一台固定攝影機與一台綁定的平板。作業員掃員工證 → 掃工單，開始**作業段**。
2. AI 在工作站旁的邊緣電腦推論：YOLO pose + **作業區**規則，判定 作業中／在場閒置／離開／無法判斷。只在狀態改變時送事件，每 5 秒送心跳，15 秒沒收到視為無法判斷。
3. AI 只計**在場人數**，不辨識身分。（ADR-0001）原始影像不上傳、不存檔，只保留 7 天**骨架片段**供申訴查證。（ADR-0004）
4. 作業段沒有暫停。作業員掃碼結束，或「離開」超過 10 分鐘由 AI **自動結束**（時間回溯到最後看到人）。結束時填寫本段完成件數。
5. 只有作業員能將工單標記為完成，並確認**實際完成總數**。

預設門檻（10 分鐘、5 秒、15 秒）可依工作站個別調整。

## 工單狀態

待開始 → 進行中 ⇄ 待續 → 已完成

## 時間計算

- 在線時間 = 有效工時 + 閒置時間（在場閒置、離開分列）+ 無法判斷時間
- 協作時工作站狀態套用到同站所有作業段；工單工時以**人時**加總。（ADR-0002）
- 在場人數 > 掃碼人數 → 標示**未登記協助**，不計工時。
- 每件標準工時定義在**產品**上；效率 = 標準工時 ÷ 有效工時。
- 作業段未填完成件數時，於工單完成時以實際完成總數扣除已填件數，依有效工時比例分攤。

## 進階分析

- 工作模式指標（每個作業段）：每件有效工時、閒置比例（在場閒置／離開分列）、中斷次數與平均連續作業長度、單人或協作。
- **標竿**：同一產品中，至少有 3 個作業段的作業員裡，每件有效工時中位數最低者。
- **效率建議**：規則計算與標竿的差距 → LLM 依指標寫成自然語言，不得自行推論數字；LLM 不可用時改用範本。
- 權限：主管看實名；作業員只看自己的數據。競賽版不做登入，以頁面區分。

## 技術

- MES 端：沿用 Flask + SQLite + 原生 JavaScript。
- AI 端：獨立 Python 程式（YOLO pose），以 HTTP 送事件給 MES。
- 訓練與展示影片：自行模擬工作站錄製（作業中、滑手機、離開、兩人協作等情境），入鏡者須簽同意書。
- 競賽規則：不得使用中國或中資的開源模型或介接工具（ADR-0005）。
