## A. AI ↔ MES 合約（`docs/api.md` 開寫前需要決定）

背景：AI 程式只知道「我是幾號工作站、畫面裡是什麼狀態、有幾個人」，不知道作業員和工單。把狀態對應到作業段、計算工時，都由 MES 負責。

### D1. 人數改變但狀態沒變，要不要送事件？

例如一直是「作業中」，但從 1 個人變成 2 個人。

- [ ] **要送：狀態或人數其中一個改變就送事件** ➡️ 建議。否則「未登記協助」的時間會算錯
- [ ] 不送，人數只透過心跳回報

決議：

### D2. 作業區設定存在哪裡？

| | (a) AI 端本地 JSON | (b) 存在 MES，AI 啟動時去抓 |
|---|---|---|
| 怎麼設定 | B 在 AI 電腦上對著畫面點出多邊形 | 主管在 MES 網頁上看截圖，點出多邊形 |
| 開發工作量 | 只有 B | B 要寫抓取程式；A 要寫設定頁面、截圖傳輸，還要多一支 API |
| 網路斷線時 | 不受影響 | 需要另外準備本地備份 |
| 隱私 | 影像完全不離開工作站 | 設定時要把一張截圖傳到 MES，是 ADR-0004 的例外 |
| 適合情境 | 工作站少（比賽現場 1 到 2 個） | 實際工廠、工作站很多 |

- [ ] **(a) 本地 JSON** ➡️ 建議。骨架片段要附上當時的作業區範圍，讓主管查證時畫得出來；(b) 寫進說明書的「未來發展」
- [ ] (b) 存在 MES

決議：

### D3. 「自動結束」由哪一端判斷？

- [ ] **MES**：AI 只回報「離開」和最後一次看到人的時間，由 MES 依門檻判斷 ➡️ 建議。AI 不知道作業段，門檻設定也在 MES
- [ ] AI 端

## C. 資源與費用

> Demo 與錄影一律在團隊自行模擬的工作站進行，不另外聯繫企業。
